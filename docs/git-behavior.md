# How git actually behaves

Everything here was **verified against real git 2.43 on Linux** unless marked
otherwise. macOS (Apple git and Homebrew git) was **not** tested when this
was written; CI exercises it on every PR (Apple git) and on every push to `main`
(Homebrew git, Intel). Treat every claim as a hypothesis that a test must pin; when git
disagrees with this file, write the failing test, adapt the code, and record the
real behaviour here.

Seeded from `docs/HANDOVER.md`. Each entry names the test that pins it once that
test exists.

## Test tracing

`OUTFIT_GIT_TRACE_FILE=<path>`: when set, `internal/gitx` appends one line per git
process it starts (the test harness uses it to pin how many git processes a command
may spawn). Unset in normal use.
| 32 | Without `sparse.expectFilesOutsideOfPatterns=true`, git notices a link standing at a skip-worktree path, clears the bit, and `git status` shows ` T <path>` (seen by hand on git 2.36.6, Apple git 2.54 and git 2.55; not pinned by a test, which is why outfit sets the key). With it (set at `--worktree` scope), the path stays skip-worktree and `git status` is clean. | `swaps-basic.txtar` (the key is set, status is clean) |
| 33 | `git reset -- <path>` (and `update-index`) drops the skip-worktree bit of a swapped path, so the link would show as a type change and could be staged. sync restores it with `git update-index --skip-worktree`. If sparse checkout was switched off by hand first, the bit must be restored **before** the sparse patterns are written again, or git sees the links as locally modified files and refuses to hide them. | `swaps-safety.txtar` |
| 34 | With `/.outfit/` in `.git/info/exclude`, `git add <path-under-.outfit>` and `git add .outfit` refuse even for TRACKED, modified files ("paths are ignored"); `git add -u .outfit`, `git add -A` and `git commit -a` work. Fix texts therefore say `git add --sparse -u .outfit` (`--sparse` because a profile that was stashed back onto disk is outside the patterns). | `swaps-refusals.txtar` (the refusal of the plain add, and the fix text) |
| 35 | `git sparse-checkout set` leaves files that have uncommitted changes in place and only warns ("not up to date … left despite sparse patterns"), exit 0: the tree is half-switched. outfit refuses to switch over such edits beforehand (`swaps-refusals.txtar`) and fails loudly, with the state recorded, if git still left files behind (`swaps-review2.txtar`, "a switch cut short"). | `swaps-refusals.txtar`, `swaps-review2.txtar` |
| 36 | `git sparse-checkout disable` leaves `core.sparseCheckout=false` and `index.sparse=false` in the config. Uninstall removes the keys outfit's sparse use added, so `git config --list` comes back byte for byte (a `true` value of `index.sparse` is someone's sparse index and stays). | `swaps-uninstall.txtar` |
| 37 | `git restore <path>` (git 2.55) runs the `post-checkout` hook, with the third argument `0` (a file checkout). outfit's sync therefore also runs after a file restore. | not pinned: it differs by git version (seen by hand on git 2.55; not checked on older versions), so no test depends on it. `swaps-hooks.txtar` pins the hooks that every version runs |
| 38 | `git add --sparse <path>` on a path git is told to expect outside the patterns stages nothing on current git; on other versions it stages the file. The guard does not rely on either: it inspects what is staged. A symlink forced into the index by hand (`update-index --cacheinfo 120000,…`) is refused by the pre-commit guard. | `swaps-safety.txtar` |
| 39 | A linked worktree has its own sparse patterns, skip-worktree bits and links: syncs run per worktree, serialized by a per-worktree lock, and ten parallel syncs across three worktrees end valid. | `swaps-parallel.txtar` |
| 40 | `git sparse-checkout set` removes a file that is only STAGED (new, never committed) from disk like any other hidden file; a later `git reset` then loses the only copy. outfit asks `git diff --cached` before it changes the patterns that hide profiles, and refuses ("staged but not committed", fix: commit) when profile files are staged but not committed. | `swaps-review.txtar` |
| 41 | `git worktree add` copies the main worktree's `config.worktree`, `sparse.expectFilesOutsideOfPatterns` included, so a linked worktree never "set" it itself. Uninstall removes it from a linked worktree whose sparse patterns are outfit's. Git's own "is this file untouched" answer also depends on `.gitattributes`/`autocrlf`: outfit asks `git status`, never compares bytes. | `swaps-paths.txtar`, `swaps-review.txtar` |
| 42 | A merge that conflicts on a swapped (skip-worktree) path replaces the link with a regular file full of conflict markers and leaves index stages 1–3; it does not write through the link. `git sparse-checkout set` then warns "unmerged and were left despite sparse patterns", exit 0. outfit leaves the path and the patterns alone while the merge is open. On git 2.36 the link that stood in the way is renamed to `<path>~cruft` (an untracked symlink `git add -A` could commit); once the merge is over outfit removes that leftover when it is its own link. | `swaps-conflict.txtar` (2.36.6 in CI shows the leftover) |
| 43 | A clean pull or merge that changes a base file under a swap changes the index blob (`git ls-files -s`) but not the skip-worktree file on disk, so the link keeps showing the profile's copy. outfit compares that blob with the one it recorded at link time (`stale`). | `swaps-stale.txtar` |
| 44 | `git worktree add` fires `post-checkout` in the new worktree with an all-zero old sha and flag `1`, after copying the main worktree's whole `config.worktree` (a pinned `outfit.profile` included, which is why outfit strips every `outfit.*` key there). `--worktree` config is only per-worktree when `extensions.worktreeConfig` is on, so the strip runs only in a linked worktree that outfit has not synced yet; `git worktree add --no-checkout` fires no hook (nothing is stripped). | `swaps-worktree-add.txtar` |
| 45 | A checkout to a commit that no longer has a tracked profile file deletes that file from disk while the profile's directory stays (it is in the sparse patterns): the link dangles until sync removes it, and the base file comes back with the pattern rewrite. | `swaps-missing-variant.txtar` |
